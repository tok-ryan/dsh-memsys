# 记忆系统小评测（第一版）

> 起因：B站 上有人吐槽"记忆插件能不能过 BM25 都是两码事，都是纯许愿"。
> 这份评测就是回答那句话的——**先量一下我们自己的底**，不管好看难看。

## 一、协议

| 项 | 内容 |
|---|---|
| 数据 | `memsys-whalesoul-data`（25 条真实记忆，鲸鱼娘导入的那批） |
| 问题 | 主人给的 5 条真实问题（q1~q5） |
| 模型 | 与主会话同档（flash），每题独立上下文，互不串题 |
| 判分 | 每题预先写死 must-have 事实点（3 个），规则匹配 + 人工复核 |

**三配置**

| 配置 | 上下文 |
|---|---|
| **A 裸模型** | 空。凭一般知识回答 |
| **B 纯 BM25** | 关键词检索 top-3，只给记忆原文 |
| **C memsys** | 同一检索算法，top-5 + 类型/权重/日期/why 元数据 |

> 诚实说明：C 没有换检索算法（memsys 的检索层本质也是关键词），差别只在**条数 + 元数据 + why 字段**。
> 所以这个评测量的是"多一点上下文和元数据有没有用"，不是"memsys 检索是否强于 BM25"。

## 二、结果

### 检索召回（金标准记忆有没有被捞到）

| 题 | 金标准条数 | B 召回 | C 召回 |
|---|---|---|---|
| q1 我对时间敏感吗 | 2 | 1 | **2** |
| q2 我现在对什么感兴趣 | 2 | 1 | 1 |
| q3 早上我给你什么定时任务吗 | 1 | 1 | 1 |
| q4 我挥霍 token 吗 | 2 | **0** | **0** |
| q5 我对你的期待是什么 | 3 | 1 | 1 |
| **合计** | **10** | **4 / 10** | **6 / 10** |

### 回答覆盖（must-have 事实点命中）

| 题 | A 裸模型 | B 纯 BM25 | C memsys |
|---|---|---|---|
| q1 时间敏感 | 1/3 | **3/3** | **3/3** |
| q2 对什么感兴趣 | 0/3 | 1/3 | 1/3 |
| q3 早上定时任务 | 1/3 | **3/3** | **3/3** |
| q4 挥霍 token | 0/3 | 0/3 | 0/3 |
| q5 对我的期待 | 0/3 | 1/3 | 1/3 |
| **合计** | **2 / 15** | **8 / 15** | **8 / 15** |

## 三、结论（照实说）

1. **有记忆 >> 没记忆**：2/15 → 8/15，四倍。这个方向是成立的。
2. **C 没比 B 强**：召回从 4/10 提到 6/10，但答案覆盖一样是 8/15——多捞到的那两条，不是判分点。
3. **瓶颈在检索，不在模型**：q4"我挥霍 token 吗"两个配置都**一条都没捞到**（记忆里写的是"花钱谨慎""怕白费力气""30 天 30.3 亿 token ¥178"，跟"挥霍"这个词没有字面交集）。q2 也一样：记忆里明明有"当前只看时政/AI/DSH 三方向"，检索却捞成了 DSH 视频那条。
4. **所以那条评论说得对**：至少在我们这套实现上，"关键词检索 + 记忆注入"并不能保证答对，**口语化提问会直接掉链子**。这不是态度问题，是检索层的问题。

## 四、局限（别拿这份报告吹牛）

- **样本只有 5 题**，主人给的；不是统计意义上的结论。
- **判分是我写的事实点 + 规则匹配**，同义表述会漏判（例如"养得更像我自己"没算进"像人一样"）。
- **C 与 B 的检索算法相同**，本评测没有验证"语义检索能不能解决 q4"。
- 只有一种模型、一次采样，没有跑多次取平均。

## 五、下一步（0.3.1 的方向，不是现在做）

1. **查询改写**：问句先抽成检索词（"挥霍 token" → "成本 / 花费 / 测算 / 浪费"），再检索。
2. **把 `why` 当检索字段**：现在 `why` 只拿来出题，没参与检索；而"挥霍"这类语义更可能出现在 why 里。
3. **评测扩到 20 题 + 加一组 BM25 对照实现**，把"记忆系统 vs 纯检索"分清楚。
4. 复现命令：`node scripts/eval-memory-prepare.mjs` 生成上下文；题目与判分口径在 `scripts/eval-memory-data.mjs`。
